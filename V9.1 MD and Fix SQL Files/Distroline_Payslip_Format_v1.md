# Distroline — Employee Payslip Format & Generation Logic (v1)

**Where this lives:** Employee Management → Payroll Runs → **Actions** column → **`Payslip`** button.
Each click renders one employee's slip for that `salary_month`, sourced entirely from stored rows — nothing typed by hand at print time. Matches the Blueprint's own stack note: *"PDF Generation — @react-pdf/renderer — Used for Payslips, Shop Statements, and all report exports that support PDF."*

Design principle carried over from the rest of Blueprint v9.1: **don't hide the math.** The whole point of §3.6/§3.8 (loan cap, `GREATEST(...,0)` floor, `balance_carried`) was to stop numbers from going invisible. The payslip below follows the same rule — every deduction shows *why*, not just *how much*.

## 3. Worked Example — Loan-Capped Case

This is the exact scenario §3.6 was built to catch (previously: Net Payable showed ₨0, balance quietly ran past -₨1 lakh with no flag). Illustrative employee, EMP-0095:

| Description | Amount (₨) |
|---|---:|
| Basic Salary | 65,000 |
| Bonus | 0 |
| **Net Salary** | **65,000** |
| Loan Installment Due | 130,000 |
| Installment Cap (30% of Basic Salary) | 19,500 |
| Loan Installment Applied *(capped, not full due)* | 19,500 |
| **Net Payable** (`GREATEST(net_salary − applied, 0)`) | **45,500** |
| **Balance Carried Forward** (`due − applied`) | **110,500** |

The slip prints a visible note here: *"Loan repayment capped at 30% of basic salary this cycle. ₨110,500 remains outstanding and carries forward — not a hidden balance."*

## 4. Generation Logic (order of operations)

```
1. Pull payroll_runs row for (employee_id, salary_month)
   → basic_salary, bonus_amount, absent_deduction, sop_violation_deduction
     are already computed and stored (Steps 1–2 of Payroll Runs: Attendance,
     Remaining Employees).

2. net_salary = basic_salary + bonus_amount
                - absent_deduction - sop_violation_deduction
   (matches the STORED generated column — do not recompute independently)

3. Loan application (Step 3 — cap logic, §3.6):
   cap_amount = basic_salary * installment_cap_pct / 100
   loan_installment_applied = MIN(loan_installment_due,
                                   cap_amount,
                                   GREATEST(net_salary, 0))
   balance_carried = loan_installment_due - loan_installment_applied

4. net_payable = GREATEST(net_salary - loan_installment_applied, 0)
   (matches the STORED generated column — never goes negative,
    shortfall always lands in balance_carried instead)

5. If employee_loans.status = 'override_active':
   render a banner — "Installment exceeds 30% cap — approved override:
   {{override_reason}}"

6. Render PDF via @react-pdf/renderer, one employee per page,
   using sections A–F above. Section B renders only if
   payroll_sops.biometric_enabled = true. Section E renders only
   if an employee_loans row exists.
```

| Emp Code | Name | Basic Salary | Bonus | Absent Ded. | SOP Ded. | Net Salary | Loan Due | Loan Applied | Net Payable | Balance Carried | Actions |
|---|---|---|---|---|---|---|---|---|---|---|---|
| EMP-0098 | Afzal Masih | 67,000 | 35,388 | 0 | 0 | 102,388 | 20,000 | 20,000 | 82,388 | 0 | **Payslip** |

`Payslip` button → opens/downloads the PDF for that `payroll_runs.id`. No recomputation happens on click — it only formats what's already stored, keeping the printed slip and the ledger permanently in agreement (same guarantee §10.1 gives the Salary Head view).
